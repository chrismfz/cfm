Traffic Rules

Per-vhost rules that allow, block, challenge or throttle requests at the edge. Rules are checked in priority order (lowest number first) and the first match wins; a rule with no conditions matches every request. Per-vhost protection toggles live on the Vhost controls page.

“Allow” is not an exemption. It only stops the rules below it from being evaluated. It does not bypass the WAF, a vhost-wide challenge or an IP block. To keep the challenge or WAF off an API / webhook path, use Challenge / WAF excludes.
Cleared browsers skip the rules. A client holding a valid clearance cookie for the vhost goes straight to the origin until it expires — so testing with your own browser after solving a challenge shows nothing.
In-path edge only. Rules are enforced by the OpenResty / Angie edge. On a server in DNAT mode they are stored but never applied.
