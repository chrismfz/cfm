Site Cache

Per-vhost edge caching. It is off for every vhost until a policy arms it, and every rule below holds whatever a policy says. The operator guide is docs/site-cache-runbook.md.

Static tier (A). css, js, fonts and images, on HTTP and HTTPS, kept as long as the origin's Cache-Control / Expires say (1 h when it sends none). It reads no request cookie: anything per-user must be marked private by the origin.
Micro tier (B). Anonymous GET/HEAD over HTTPS, for 1–60 s.
Never cached, on either tier: a request with Authorization, a response with Set-Cookie / private / no-store, a non-200, panel and webmail hosts. The micro tier also skips session cookies, credential headers, partial-page requests and admin paths.
SITE_CACHE = 0 on this node: nothing is cached and the edge does not read these policies. They resume as they are when it is set back to 1; after a purge, reload the edge before that (runbook §8).

A recipe applies a ready-made policy to one or more vhosts. It changes only the tier it names: a vhost that already caches static assets keeps them.

Check one URL

Run this on the server itself. The edge adds an X-CFM-Cache header only for trusted sources (the box, its own IPs, IGNORE_IPS / IGNORE_NETS). Port 443 on the box reaches the origin, not the edge, hence :9043.

Enter a valid vhost to build the command.

  • status=HIT (or MISS, EXPIRED, BYPASS…) is nginx's cache verdict for a request that went through a cache location.
  • microcache=would/5s means the micro tier would cache this page for 5 s; microcache=bypass:<reason> says why not (auth:<cookie>, path, method…). Both show even in a dry run.
  • A request from the box skips the WAF and challenge, so for a page the stamp shows the would-verdict only; real traffic's verdict is ucache="…" in the edge's access.log.
  • No header at all: SITE_CACHE = 0, an untrusted source, no policy for the host yet (the edge polls about every 60 s), an opt-out no wildcard covers, or the :9080 listener.

Hit counts

Live counts from the edge, pushed about every 60 s and only for armed vhosts, both tiers in one row. They run since the edge last restarted, and this view is empty until the next push after a daemon restart or any save of detectors.conf. A micro-tier page that is declined, or only evaluated in a dry run, is not counted: use the debug stamp for those. BYPASS is a counted request that could not use the cache, usually an asset of a vhost whose static tier is off, or a request with Authorization.
